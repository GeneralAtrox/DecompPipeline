## Why those 16 fail (the cause, found)
The function stores two pointers at sp+0x20 and sp+0x24 (8c05edf2, 8c05edfc) before any pair test, in every path with a
nonzero shape count. `candidate` lives at sp+0x20, so its first two words (point.x, point.y) are those pointers until the
callee overwrites them. The oracle's mocked table callee writes nothing, so on a hit the original copies the two pointers
into `out`. The out-pointer step delivers only bytes the original did not store itself (the D line shows `xxxxxxxxxxxxxxxx`
for those 8 bytes), and readable C has no variable that holds that pointer there: it copies 0. Vectors with both counts 0
(no stores) pass; vectors with a nonzero count that copy fail. On the console the callee fills all of `candidate`
before the copy, so these vectors cannot occur; but no hint can reach the two-box path without them.

## What would change it
- `mock_write_facts` for the 16 callees, `{"r4": 28}` each: the mocked callee then writes the contact on both sides, so the
  stale words are overwritten as on the console. It needs evidence per callee that it writes the whole LibContact on every
  hit (16 functions' asm, not done: the readable sources of 8c05e374 and others delegate the writes), and
  `tools/selective_restamp.py --change mockwrite` assumes NO facts listed before, while TC already lists several callees
  (8c04b328, 8c048914, 8c0489a8 and 8c01b1b6 among them): it needs a way to take the baseline with only the new callees left out.
- Or a judge rule that drops a vector whose copy reads bytes the original stored itself into the callee's out buffer (the
  console's callee always overwrites them). That is a judge change: 0-lost-kill proof on every function with an
  out-pointer spec.

Nothing was accepted with a lost kill, no verdict edited, no real catch dropped.
